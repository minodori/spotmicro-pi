## 1. 지금 규칙 기반이 못 하는 것

규칙 기반 보행은 이미 동작한다. 초속 50mm 로 1m 를 20초에 걸어간다.
그러면 강화학습은 왜 하는가. 걷는 20초를 지켜보면 답이 나온다.

### 1.1 오른쪽으로 밀려서 사람이 잡아줘야 한다

[work11 §5단계](work11.md)에서 1m 직진을 재는 동안 왼쪽으로 두세 번 보정을 넣었다.
로봇이 스스로 직진하지 못하기 때문이다.

원인은 조립 오차다. 각도를 실측해보니 다리마다 이만큼 차이가 났다.

| 다리 | 오차 |
|---|---:|
| FL | +7° |
| FR | +7° |
| RL | **+15°** |
| RR | +2° |

혼(horn)이 스플라인에 물리는 위치가 서보마다 다르고, 한 칸이 14.4° 라서
재체결할 때마다 이만큼 튄다 ([work11 §6.6](work11.md)).

오차 자체는 조립을 다시 하면 줄어든다. 그런데 아무리 잘 맞춰도 시간이 지나면
다시 틀어지고, 로봇은 자기가 틀어졌다는 걸 알 방법이 없다. 구조가 이렇게 되어 있다.

```
규칙 기반 = 개루프(open loop)

  발끝 궤적 생성 → 역기구학 → 서보 명령 → 끝
                                          ↑
                            결과를 되돌아보는 경로가 없다
```

몸이 기울어져도, 한쪽으로 밀려도 다음 스텝의 명령은 똑같이 나간다.
사람이 트림 값을 넣어줘야 비로소 고쳐진다.

### 1.2 파라미터를 사람이 찾아야 하는데 서로 얽혀 있다

`Tt2800` 을 시도했던 일이 이 문제를 잘 보여준다.

```
목표     무릎 각속도를 낮춰 서보 부담을 줄이자
방법     주기를 1400 → 2800ms 로 늘림 (해석적으로는 최적)
결과     속도가 49 → 34mm/s 로 떨어짐
원인     속도는 보폭에서 나오는데 보폭(-70)을 그대로 뒀다
```

조절할 축이 여러 개인데 서로 영향을 준다. 한 축만 보고 최적화하면
다른 축이 나빠져서 전체 성능이 떨어질 수 있다.

| 축 | 올리면 |
|---|---|
| 보폭 `Sl` | 속도 ↑, 무릎 각속도 ↑ |
| 주기 `Tt` | 속도 ↓, 무릎 각속도 ↓ |
| 스윙 비율 | 발 들림 ↑, 네 발 지지 ↓ (안정성 ↓) |
| 몸통 높이 | 안정성 ↓, 보폭 여유 ↑ |

### 1.3 바닥이 바뀌면 값을 다시 맞춰야 한다

거실 장판에서 맞춘 값이 카펫에서는 그대로 쓰이지 않는다.
마찰이 달라지면 발이 미끄러지고, 미끄러진 만큼 실제 보폭이 명령값보다 작아진다.
결국 바닥마다 사람이 다시 튜닝해야 한다.

### 1.4 외란에 반응하지 못한다

궤적이 미리 정해져 있어서 옆에서 밀어도 명령이 달라지지 않는다. 그대로 넘어진다.

## 2. 강화학습이 주는 것

| | 규칙 기반 | 강화학습 |
|---|---|---|
| 발끝 궤적 | 사람이 설계 | 보상만 정의하면 정책이 찾음 |
| 제어 구조 | 개루프 | **폐루프** — 자세를 보고 매 스텝 보정 |
| 편향 | 사람이 트림으로 | 스스로 보정 |
| 지형 변화 | 재튜닝 | 도메인 랜덤화로 흡수 |
| 외란 | 무반응 | 학습 중에 밀어봤으니 버팀 |

### 2.1 폐루프가 무엇을 바꾸는가

```
관측 (IMU 각속도, 투영 중력, 속도 명령, 이전 행동)
        ↓
     정책 (신경망)
        ↓
관절 각도 12개  →  서보  →  로봇이 움직임
        ↑                        │
        └────────────────────────┘
              50Hz 로 되돌아온다
```

로봇이 기울어지면 IMU 가 그것을 읽고, 정책이 그 값을 보고 다음 명령을 바꾼다.
1.1 에서 본 오른쪽 편향은 이 경로만 있으면 원리적으로는 자동으로 보정된다.

### 2.2 도메인 랜덤화 — 학습 중에 조건을 흔들어 둔다

시뮬레이터에서 학습할 때 조건을 매번 조금씩 바꿔가며 돌리는 방법이다.
실물이 시뮬과 다를 수밖에 없으니, 그 차이를 학습 중에 미리 겪게 하는 것이다.
우리는 실측 근거가 있는 값으로 흔든다.

| 흔드는 것 | 폭 | 근거 |
|---|---|---|
| **서보 영점 오차** | **±8°** | 실측 FL+7 FR+7 RL+15 RR+2, 혼 한 칸 14.4° |
| 무게중심 전후 | ±15mm | work11 §6.18 실측 자체가 불일치 |
| 링크별 질량 | ×[0.8, 1.2] | 총 2.2kg 만 실측, 배분은 추정 |
| 지면 마찰 | ×[0.6, 1.4] | 장판·카펫 |
| 제어 지연 | 0~2 스텝 | I2C + 서보 응답 |

혼이 한 칸 어긋난 로봇을 학습 중에 한 번도 겪어보지 않은 정책은
실물에서 그런 상황을 만나면 넘어진다. 우리는 그 값을 실제로 재 뒀다.

## 3. 대가

### 3.1 관측할 수 있는 것이 부족하다

```
서보 위치 피드백   없음   DS3235 는 되읽기 불가, PCA9685 는 쓰기 전용
IMU               미설치  BOM 에는 있지만 아직 안 붙임
```

4족보행 RL 이 보통 쓰는 관측은 관절각, 관절 각속도, 동체 자세 세 가지인데
우리는 앞의 둘을 실물에서 얻을 수 없다.

이럴 때 흔히 그 자리에 직전에 명령한 값을 대신 넣는다. 그런데 실측을 보면
이 대체가 위험하다. 40mm 를 명령했을 때 실제로 들린 높이가 20mm 를 명령했을 때보다
오히려 낮았다. 서보가 명령을 따라가지 못하는 구간에서는 명령값과 실제 각도가
크게 벌어진다는 뜻이다.

### 3.2 관측을 두 가지로 나눠서 비교한다

| | 구성 | 차원 |
|---|---|---|
| **A안** | 동체각속도 3, 투영중력 3, 속도명령 3, **관절각 12, 관절각속도 12**, 이전행동 12 | 45 |
| **B안** | 동체각속도 3, 투영중력 3, 속도명령 3, **이전행동 12 × 5프레임** | 69 |

A안은 서보 피드백이 있다고 가정한 구성이고, B안은 지금 하드웨어로 실제 가능한 구성이다.
둘을 같은 조건에서 학습시켜 성능이 얼마나 차이 나는지 잰다.

| 결과 | 판단 |
|---|---|
| 차이가 작다 | 지금 하드웨어로 충분하다 |
| 차이가 크다 | 포텐쇼미터 탭이나 시리얼 버스 서보로 바꿀 가치가 있다 |

**결론: 센서를 추가할지는 이 측정 결과를 보고 정한다.**

> ⚠️ B안을 학습시킬 때 주의할 것 — 시뮬레이터에서도 `data.qpos`(실제 관절각)가 아닌
> 직전에 명령한 값을 넣어야 한다. 실물에 없는 정보를 시뮬에서 주고 학습하면
> 이식할 때 실패한다.

### 3.3 동체 선속도는 두 안 모두 관측에서 뺀다

상태 추정기도 깊이 카메라도 없어서 실물에서는 얻을 수 없는 값이다.
학습할 때 이 값에 의존해버리면 실물 이식 자체가 불가능해진다.
다만 보상과 종료 조건에는 써도 된다. 학습 중에만 쓰고 실행할 때는 필요 없기 때문이다.

### 3.4 RL 이 더 낫다는 보장은 없다

규칙 기반이 이미 걷고 있으니 비교해봐야 안다.
그래서 로드맵에 "규칙 기반 보행과의 정량 비교"를 넣어 두었다.

## 4. 정리

규칙 기반은 걷긴 하는데 20초에 두세 번 사람이 방향을 잡아줘야 한다.
조립 오차가 쌓이는데 로봇이 자기가 틀어진 것을 알 방법이 없기 때문이다.

강화학습은 IMU 로 자세를 보면서 매 스텝 관절을 조정하므로 그 보정을 스스로 한다.
바닥이나 부하가 바뀌어도 사람이 파라미터를 다시 찾을 필요가 없다.

대신 지금 하드웨어는 서보 피드백이 없어서 정책이 볼 수 있는 정보가 적다.
그래서 관측을 A안과 B안으로 나눠 비교하고, 그 차이를 근거로 센서 추가 여부를 정한다.

이 흐름이 한계점과 이식 가능성을 이어준다.

```
오른쪽 편향 (관측된 한계)
    → 개루프의 구조적 문제
    → 폐루프가 필요하다
    → 그러려면 자세를 봐야 한다 (IMU)
    → 지금은 미설치
    → 관측 A안/B안 비교로 그 가치를 측정
    → 측정 결과가 센서 추가 결정의 근거
```
