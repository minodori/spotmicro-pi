# SpotMicro Week 12 — 강화학습이 왜 필요한가

> 작성일: 2026-08-21
> 성격: 학습 노트. 이 로봇에서 **실제로 관측된 것**만 근거로 정리한다.

---

## 0. 왜 이 문서를 쓰는가

규칙 기반 보행이 이미 걷고 있다. 초속 50mm 로 1m 를 20초에 간다.
그런데도 강화학습을 하는 이유를 한 문장으로 답할 수 있어야 한다.

일반론("RL 은 최적 정책을 찾는다")이 아니라, **우리 로봇이 지금 못 하는 것**에서
출발한다.

---

## 1. 규칙 기반이 지금 못 하는 것 — 관측된 사실

### 1.1 우측 편향 — 20초에 두세 번 사람이 잡아준다

[work11 §5단계 측정](work11.md)에서 1m 직진을 재는 동안 좌측 보정을 2~3회 넣었다.
로봇이 스스로 직진하지 못한다.

원인은 조립 오차다. 각도 실측에서 다리마다 이만큼 차이가 났다.

| 다리 | 오차 |
|---|---:|
| FL | +7° |
| FR | +7° |
| RL | **+15°** |
| RR | +2° |

혼(horn)이 스플라인에 물리는 위치가 서보마다 다르고, **한 칸이 14.4°** 라
재체결하면 이만큼 튄다 ([work11 §6.6](work11.md)).

문제는 오차 자체가 아니라 **로봇이 자기가 틀어지는 걸 모른다**는 것이다.

```
규칙 기반 = 개루프(open loop)

  발끝 궤적 생성 → 역기구학 → 서보 명령 → 끝
                                          ↑
                            결과를 되돌아보는 경로가 없다
```

기울어져도, 한쪽으로 밀려도, 다음 스텝의 명령은 똑같다.
사람이 트림 값을 넣어줘야 고쳐진다.

### 1.2 파라미터를 사람이 찾아야 하고, 서로 얽혀 있다

`Tt2800` 사례가 이것을 잘 보여준다.

```
목표     무릎 슬루를 낮춰 서보 부담을 줄이자
방법     주기를 1400 → 2800ms 로 늘림 (해석적으로 최적)
결과     속도가 49 → 34mm/s 로 떨어짐
원인     속도는 보폭에서 나오는데 보폭(-70)을 그대로 뒀다
```

축이 여러 개고 서로 영향을 준다. **한 축만 최적화하면 전체가 나빠질 수 있다.**
사람이 손으로 찾으면 이런 함정에 빠진다.

| 축 | 올리면 |
|---|---|
| 보폭 `Sl` | 속도 ↑, 무릎 슬루 ↑ |
| 주기 `Tt` | 속도 ↓, 슬루 ↓ |
| 스윙 비율 | 발 들림 ↑, 네 발 지지 ↓ (안정성 ↓) |
| 몸통 높이 | 안정성 ↓, 보폭 여유 ↑ |

### 1.3 지형이 바뀌면 다시 튜닝

거실 장판에서 맞춘 값이 카펫에서 그대로 맞지 않는다.
마찰이 달라지면 발이 미끄러지고, 미끄러지면 보폭이 명령값보다 작아진다.

### 1.4 밀면 넘어진다

궤적이 고정이라 외란에 대한 반응이 없다.

## 2. 강화학습이 주는 것

| | 규칙 기반 | 강화학습 |
|---|---|---|
| 발끝 궤적 | 사람이 설계 | **보상만 정의하면 정책이 찾음** |
| 제어 구조 | 개루프 | **폐루프** — 자세를 보고 매 스텝 보정 |
| 편향 | 사람이 트림으로 | **스스로 보정** |
| 지형 변화 | 재튜닝 | **도메인 랜덤화로 흡수** |
| 외란 | 무반응 | **학습 중에 밀어봤으니 버팀** |

### 2.1 핵심은 "폐루프"다

```
관측 (IMU 각속도, 투영 중력, 속도 명령, 이전 행동)
        ↓
     정책 (신경망)
        ↓
관절 각도 12개  →  서보  →  로봇이 움직임
        ↑                        │
        └────────────────────────┘
              50Hz 로 되돌아온다
```

**로봇이 기울어진 것을 보고 다음 명령을 바꾼다.** 이게 규칙 기반과의 근본적 차이다.
1.1 의 우측 편향은 이 경로만 있으면 원리적으로 자동 보정된다.

### 2.2 도메인 랜덤화 — 미리 여러 로봇을 겪게 한다

학습 중에 일부러 조건을 흔든다. 우리는 실측 근거가 있는 값으로 흔든다.

| 흔드는 것 | 폭 | 근거 |
|---|---|---|
| **서보 영점 오차** | **±8°** | 실측 FL+7 FR+7 RL+15 RR+2, 혼 한 칸 14.4° |
| 무게중심 전후 | ±15mm | work11 §6.18 실측 자체가 불일치 |
| 링크별 질량 | ×[0.8, 1.2] | 총 2.2kg 만 실측, 배분은 추정 |
| 지면 마찰 | ×[0.6, 1.4] | 장판·카펫 |
| 제어 지연 | 0~2 스텝 | I2C + 서보 응답 |

> **혼이 한 칸 어긋난 로봇을 본 적 없는 정책은 실물에서 그걸 만나면 넘어진다.**
> 우리는 그 값을 실제로 재 뒀다.

## 3. 공짜가 아니다 — 정직하게

### 3.1 지금 하드웨어는 관측이 부족하다

```
서보 위치 피드백   없음   DS3235 는 되읽기 불가, PCA9685 는 쓰기 전용
IMU               미설치  BOM 에는 있지만 아직 안 붙임
```

4족보행 RL 의 표준 관측은 **관절각 + 관절각속도 + 동체 자세**인데,
우리는 앞의 둘을 실물에서 얻을 수 없다.

흔히 그 자리에 **이전에 명령한 값**을 대신 넣지만, 실측이 그 대체가 위험함을 보여준다 —
40mm 를 명령했을 때 실제로 들린 높이가 20mm 명령보다 **낮았다.**
서보가 명령을 못 따라가는 구간에서 명령값과 실제 각도가 크게 벌어진다.

### 3.2 그래서 관측을 두 가지로 나눠 비교한다

| | 구성 | 차원 |
|---|---|---|
| **A안** | 동체각속도 3, 투영중력 3, 속도명령 3, **관절각 12, 관절각속도 12**, 이전행동 12 | 45 |
| **B안** | 동체각속도 3, 투영중력 3, 속도명령 3, **이전행동 12 × 5프레임** | 69 |

같은 조건에서 학습시켜 성능 차를 잰다.
**그 차이가 곧 피드백 센서를 추가할지 판단하는 근거**가 된다.

- 차이가 작다 → 지금 하드웨어로 충분하다
- 차이가 크다 → 포텐쇼미터 탭 또는 시리얼 버스 서보로 교체할 가치가 있다

추측이 아니라 **측정으로 하드웨어 사양을 정하는 것**이다.

> B안에서 주의: 시뮬레이터에서도 `data.qpos`(실제 관절각)가 아니라 **직전에 명령한
> 값**을 넣어야 한다. sim 에서 실물에 없는 정보를 주고 학습하면 이식이 실패한다.

### 3.3 동체 선속도는 두 안 모두 관측에서 제외

상태 추정기도 깊이 카메라도 없어 실물에서 얻을 수 없다.
학습 단계에서 그것에 의존하면 이식 자체가 불가능해진다.
(보상과 종료 조건에는 써도 된다 — 그건 학습 중에만 쓰는 특권 정보다.)

### 3.4 RL 이 더 낫다는 보장은 없다

규칙 기반이 이미 걷고 있다. 비교해봐야 안다.
그래서 보고서 로드맵에 **"규칙 기반 보행과의 정량 비교"** 를 넣었다.

## 4. 한 문장으로

> 규칙 기반은 걷긴 하는데 20초에 두세 번 사람이 방향을 잡아줘야 한다.
> 조립 오차가 누적되는데 로봇이 자기가 틀어지는 걸 모르기 때문이다.
>
> 강화학습은 IMU 로 자세를 보면서 매 스텝 관절을 조정하니 그 보정을 스스로 한다.
> 지형이나 부하가 바뀌어도 사람이 파라미터를 다시 찾을 필요가 없다.
>
> 대신 지금 하드웨어는 서보 피드백이 없어 정책이 볼 수 있는 정보가 적다.
> 그래서 관측을 두 가지로 나눠 비교하고, 그 차이를 센서 추가의 근거로 삼는다.

---

## 5. 보고서에서의 위치

이 논리가 **한계점**과 **이식 가능성**을 연결한다.

```
우측 편향 (관측된 한계)
    → 개루프의 구조적 문제
    → 폐루프가 필요하다
    → 그러려면 자세를 봐야 한다 (IMU)
    → 지금은 미설치
    → 관측 A안/B안 비교로 그 가치를 측정한다
    → 측정 결과가 센서 추가 결정의 근거
```

약점 고백이 아니라 **"측정해서 하드웨어 사양을 정한다"는 방법론**이 된다.
