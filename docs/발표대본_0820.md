# 부록 A. 외울 숫자는 세 개뿐입니다

대본은 파라미터를 거의 쓰지 않습니다. 이 셋만 기억하세요.

```
31%        공개 코드의 다리 길이가 실물보다 짧았던 정도
0 / 2 / 2  검증이 맞은 세 층위 — 기하 0.0000mm, 동역학 2%, 거동 2%
50mm/s     실측 보행 속도. 이론값과 정확히 일치 (미끄러짐 0)
```

나머지는 **"자세한 건 저장소 일지에 있습니다"** 로 넘기셔도 됩니다.

# 부록 B. 파라미터 치트시트 — 질문 나올 때만

## 보행 파라미터

| 이름 | 값 | 한 줄 설명 |
|---|---|---|
| **보폭** `Sl` | 70 mm | 한 걸음에 발이 **앞뒤로 움직이는 거리**. 클수록 빠르다 |
| **주기** `Tt` | 1400 ms | 네 발이 **한 바퀴 도는 데 걸리는 시간**. 짧을수록 빠르다 |
| **스윙 비율** | 0.143 | 한 다리가 **공중에 떠 있는 시간의 비율**. 나머지는 땅을 딛는다 |
| **네 발 지지** | 71% | 네 발이 **모두 땅에 있는 시간의 비율**. 높을수록 안정, 낮을수록 빠름 |
| **발 들어올림** `Sh` | 20 mm | 발을 **얼마나 높이 드는가** |
| **몸통 높이** | 110 mm | 지면에서 몸통까지. 낮을수록 안정 |
| **피치 트림** | +3 | 앞뒤 기울기 미세 보정 |

## 이 한 줄만 알면 됩니다

```
속도 = 보폭 ÷ 주기 = 70 mm ÷ 1.4 초 = 50 mm/s
```

**그리고 실측이 정확히 50 이었습니다.** 이게 "미끄러짐 0" 의 의미입니다.
계산한 만큼 정확히 갔다는 뜻이고, 발바닥 패드 덕분입니다.

> 말하실 때: *"보폭 나누기 주기가 속도입니다. 70밀리를 1.4초에 가니까 초속 50밀리.
> 실제로 재보니 딱 50 나왔습니다."*

## 서보 관련

| 이름 | 값 | 한 줄 설명 |
|---|---|---|
| **무릎 슬루** | 323°/s | 무릎이 **얼마나 빨리 도는가**. 서보 성능의 한계치 |
| DS3235 정격 | 545°/s | 무부하 기준. 지금은 그 **59%** 를 쓰고 있다 |
| **서보 추종률** | 100% | 20mm 들라고 명령했더니 **정확히 20mm** 들렸다 |

> 말하실 때: *"서보가 얼마나 빨리 돌 수 있는지가 보행 속도의 상한입니다.
> 지금은 정격의 59%만 쓰고 있어서 여유가 있습니다."*

## 왜 빠르게 하려면 둘을 같이 올려야 하나

질문이 나오면 이렇게만 말하세요.

```
주기를 줄이면 빨라지는데, 그만큼 다리가 더 빨리 움직여야 합니다.
서보가 못 따라가면 발이 계획한 자리에 안 떨어지고 미끄러집니다.
그래서 주기만 줄이는 게 아니라 서보가 낼 수 있는 속도를 보면서
같이 올려야 합니다.
```

⚠️ 실제로 저희가 이걸로 한 번 실수했습니다 — 무릎 속도만 최적화하고
보폭을 그대로 뒀더니 **오히려 느려졌습니다.** 속도는 보폭에서 나오는데
그걸 안 건드렸던 겁니다. 시뮬레이션에서 미리 잡았습니다.

## 강화학습 쪽 (물어보면)

| 이름 | 한 줄 설명 |
|---|---|
| **관측** | 정책이 매 순간 보는 정보 — 기울기, 각속도, 속도 명령, 이전 행동 |
| **행동** | 정책이 내놓는 것 — **12개 관절의 각도**. 토크가 아니다 |
| **50 Hz** | 초당 50번 판단하고 명령한다 |
| **도메인 랜덤화** | 학습 중에 질량·마찰·지연·서보 오차를 일부러 흔든다. 실물이 시뮬과 다를 걸 알기 때문 |

> **왜 토크가 아니라 각도인가** — 이건 꼭 알아두세요. 자주 나올 질문입니다.
>
> *"저희 서보는 각도만 받습니다. 토크 명령을 못 받아요.
> 그래서 정책이 토크를 내놓게 학습하면 실물에 올릴 방법이 아예 없습니다.
> 처음부터 각도를 내놓게 설계했습니다."*
