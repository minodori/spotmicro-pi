## A. 용어 — 셋 다 해당

- [ ] **"게이트" 를 "검증 항목" 으로.** gate 를 그대로 쓴 말입니다.

```
검증 게이트 8종                      -> 검증 항목 8가지
8게이트가 실물과 일치하는지 알려준다  -> 여덟 항목이 실물과 맞는지 확인해준다
단일 출처 + 검증 8게이트              -> 단일 출처 + 검증 8항목
검증 게이트가 가리키던 무게중심 이탈  -> 검증에서 걸렸던 무게중심 이탈
표 머리 "게이트 | 결과"               -> "검증 항목 | 결과"
```

여덟 개가 순서대로 진행되는 단계가 아니라 각각 독립적으로 확인하는 조건이라
"단계" 보다 "항목" 이 맞습니다. 관문이라는 뜻은 바로 뒤에 붙는 "하나라도
실패하면 학습이 시작되지 않는다" 가 이미 전달합니다.

- [ ] **"실측 슬루" 를 "요구 각속도" 로.** 서보에 위치 피드백이 없어 관절이
      실제로 그 속도로 돌았는지 확인할 수 없습니다. 우리가 가진 것은 궤적이
      요구하는 속도이고, `start_automatic_gait.py:94` 가 명령값의 차분으로
      계산합니다. 같은 문서에 "관절 위치를 되읽을 수 없다" 가 있어 그대로 두면
      앞뒤가 맞지 않습니다.

      원을 넘어" 로 고쳐져 있습니다.

- [ ] **배속을 하나로.** 기준선이 달라 세 곳이 어긋납니다.

```
docs/결과보고서.md        2.8배   (0.171 / 0.062)
checkpoints/README.md     3.4배   (0.171 / 0.050)
docs/영상시나리오.md      3.4배
```

  둘 다 실측이지만 기준이 다릅니다. 어느 쪽을 쓰든 **기준선을 함께 적어야**

  맞추고 "규칙 기반 0.050 m/s 대비" 를 명시하는 쪽이 낫습니다.

- [ ] **`make gait-check` 설명의 "속도 4% 이내" 를 "8% 이내" 로.** 실측은

## D. 저장소 코드 · README — COO / CTO

- [ ] **실물 실행 명령이 실패합니다.** 실제로 돌려 확인했습니다.

```
$ python RaspberryPi/start_automatic_gait.py
ModuleNotFoundError: No module named 'Kinematics'

맞는 명령
$ cd RaspberryPi && python start_automatic_gait.py
```

  `start_automatic_gait.py:8` 이 `sys.path.append("..")` 라, 저장소 루트에서
  실행하면 `..` 가 저장소 밖을 가리킵니다. 고칠 곳은 네 군데입니다.

```
README.md                  "python RaspberryPi/start_automatic_gait.py"
docs/결과보고서.md          같은 줄 두 곳
docs/결과보고서_초안.md     같은 줄 한 곳
```

  **10월 기능테스트에서 잡히는 종류입니다.** 근본 해결은 `sys.path.append("..")`
  대신 파일 위치 기준 경로를 쓰는 것이지만 코드 변경이라 CTO 영역입니다.
