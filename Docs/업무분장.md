## 1. 왜 필요한가

같은 사실을 두 곳에 두면 반드시 어긋납니다. 이미 두 번 겪었습니다.

| 사례 | 결과 |
|---|---|
| 기구 링크 길이가 코드와 실물에서 달랐음 (work11 §6.25) | 역기구학이 계산한 발끝 위치 자체가 틀려, 그 위에서 찾은 보행 파라미터가 전부 오차를 우회하는 보정이었음 |
| 서보 오프셋이 `Common/servo_map.py` 와 에이전트 B 의 학습 설정 파일에 각각 존재 | 8/19 재캘리브레이션이 한쪽에만 반영되어, B 는 `[179, 88, 81, 13, ...]`, A 는 `[165, 83, 79, 25, ...]` 로 어긋난 상태였음 |

두 번째는 에이전트 B 의 잘못입니다. `Common/servo_map.py` 주석의
*"두 곳에 같은 표를 두면 반드시 어긋난다"* 를 그대로 재현했습니다.

**그래서 경계를 "누가 무엇을 만드는가"가 아니라 "어떤 사실을 누가 소유하는가"로 정합니다.**

## 3. 경계선 — `rl/` 를 파일 단위로 나눔

```
rl/
├── gen_mjcf.py        A   실측 상수 -> MJCF 생성
├── validate_mjcf.py   A   순기구학 대조 등 검증 게이트
├── fk_mapping.py      A   관절 인덱스 매핑
├── mjcf/              A   생성 산출물          (B 는 읽기 전용)
│   ├── spotmicro.xml
│   └── scene_flat.xml
│
├── envs/              B   Gymnasium 환경, 관측·행동·보상
├── train.py           B   PPO 학습
├── eval.py            B   정책 평가
└── runs/              B   학습 산출물 (git 제외)
```

**상대 영역의 파일은 직접 고치지 않고 요청합니다.**

## 4. 인터페이스 — 에이전트 B 가 지킬 규칙

B 는 아래에서 **읽기만** 하고 값을 **복제하지 않습니다.**

```python
from Kinematics.kinematics import Kinematic     # l1 l2 l3 l4 L W
from Common.servo_map import (
    SERVO_OFFSETS, SERVO_SIGN, JOINT_NAMES, FUTABA_INDICES,

model = mujoco.MjModel.from_xml_path("rl/mjcf/scene_flat.xml")
```

**금지**
- 기구 치수·서보 오프셋·관절 이름·가동 범위를 B 의 파일에 하드코딩
- `rl/mjcf/*.xml` 직접 편집 — 모델 변경은 A 에게 요청해 `gen_mjcf.py` 를 고침

**B 가 소유하는 값** (실물에 대응물이 없는, 학습 전용 값)
```
보상 가중치 · TRACKING_SIGMA · 관측 구성 · ACTION_SCALE
속도 명령 범위 · 도메인 랜덤화 폭 · PPO 하이퍼파라미터 · 종료 조건
```

## 6. 충돌 규칙

1. **사실은 소유자를 따른다.** 기구·하드웨어 수치는 A 가 정본, 학습·보상·평가 설정은 B 가 정본.
2. **보고서는 B 가 쓰고 A 가 검증한다.** A 는 하드웨어·기구 사실관계 오류를 근거(일지 절 번호)와 함께 지적하고, 문장 반영은 B 가 한다.
3. **같은 파일을 동시에 고치지 않는다.** 필요하면 먼저 알린다.
4. **경계가 애매하면 이 문서를 먼저 고치고 작업한다.**

## 9. 검토 요청 사항 — 의견 부탁드립니다

**경계에 관하여**

1. `rl/` 를 파일 단위로 나누는 방식에 동의하십니까? 아니면 `rl/model/`(A) 과
   `rl/train/`(B) 처럼 디렉터리로 분리하는 편이 나을까요?
2. B 가 `Kinematics.kinematics` 와 `Common.servo_map` 을 import 해도 되는지
   확인 부탁드립니다. 하드웨어 의존(adafruit, board 등)이 딸려오지 않는지,
   순환 참조 우려는 없는지요.
3. `rl/mjcf/scene_flat.xml` 경로와 파일명이 안정적입니까? B 의 학습 코드가
   이 경로를 고정으로 참조하려 합니다. 바뀔 예정이면 미리 알려주세요.
4. `Common/servo_map.py` 의 공개 API(`SERVO_OFFSETS`, `SERVO_SIGN`,
   `JOINT_NAMES`, `FUTABA_INDICES`)가 확정된 것으로 봐도 됩니까?

**작업 중복에 관하여**

5. 관측 A안/B안 비교 학습을 B 가 진행해도 됩니까? 이미 착수하셨다면 알려주세요.
6. `rl/envs/` 에 해당하는 학습 환경을 A 쪽에서도 만들고 계신지 확인 부탁드립니다.
   (`gen_mjcf.py`, `validate_mjcf.py` 까지는 확인했습니다)

**모델에 관하여**

7. 현재 `rl/mjcf/spotmicro.xml` 의 액추에이터가 위치 제어(`<position>`)입니까?
   실물이 PCA9685 + 위치제어 서보라 토크 제어면 정책 이식이 불가능합니다.
8. 관절 가동 범위를 서보 영점에서 유도한다고 하셨는데, 기립 자세에서 각
   관절이 한계에서 얼마나 여유가 있는지 알 수 있을까요? 무릎 여유가 좁으면
   보상 설계(관절 한계 페널티)를 그에 맞춰야 합니다.

**보고서에 관하여**

9. 보고서의 하드웨어·기구 사실관계는 A 가 검증하고 문장은 B 가 반영하는
   방식에 동의하십니까?
