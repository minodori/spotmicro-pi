## 프로젝트 세부 내용

### 개발배경 및 목적

```
상용 4족보행 로봇은 수천만원대여서 학습과 연구 목적으로 접근하기 어렵다. 대안으로
널리 쓰이는 오픈소스 SpotMicro는 부품비가 100만원대지만, 공개된 코드를 그대로
따라가도 로봇이 제대로 걷지 않는다는 문제가 있다.

본 팀은 그 원인을 규명하는 것에서 출발했다. 결론은 소프트웨어가 아니라 모델에
있었다. 공개 코드의 기구학 링크 길이가 실제 조립된 로봇과 크게 달랐고, 역기구학이
계산한 발끝 위치 자체가 틀려 있었다. 그 위에서 아무리 보행 파라미터를 조정해도
오차를 우회하는 보정에 불과했다.

본 프로젝트의 목적은 두 가지다. 첫째, 실측을 통해 모델을 실물과 일치시켜 저비용
하드웨어에서 안정적인 보행을 성립시키는 것. 둘째, 그 위에 물리 시뮬레이션 기반
강화학습 보행 파이프라인을 구축해, 규칙 기반 보행의 한계인 지형 적응성을 넘어서는
것이다. 두 결과와 11주간의 개발 과정 전체를 오픈소스로 공개한다.
```

### 시스템 구성 및 아키텍처

```
[실측 기구 파라미터] ─┬─→ 역기구학 보행 (규칙 기반)  ─→ CM4 ─→ PCA9685 ×2 ─→ 서보 12개
                      │        ↑ 폰 웹 UI 실시간 튜닝              ↑
                      └─→ MuJoCo 모델 ─→ PPO 학습 ─→ policy ──────┘
                                                     (50 Hz 추론)
```

```
두 갈래의 보행 제어가 동일한 기구 파라미터와 동일한 서보 인터페이스를 공유한다.
실측으로 확정한 링크 길이가 역기구학과 시뮬레이션 모델 양쪽의 단일 기준이 되며,
어느 쪽에서 만든 관절 각도든 같은 경로로 서보에 전달된다.

강화학습 정책은 토크가 아니라 기본 자세로부터의 관절 각도 변위를 출력한다.
실물이 위치제어 서보로 구동되어 토크 명령을 받을 수 없기 때문이며, 이 설계 덕분에
학습한 정책을 별도 변환 없이 실물 제어 루프에 넣을 수 있다.
```

| 항목 | 값 |
|---|---|
| 관측 (A안) | 45차원 — 동체 각속도 3, 투영중력 3, 속도명령 3, 관절각 12, 관절각속도 12, 이전행동 12 |
| 관측 (B안) | 33차원 — 관절 피드백을 뺀 구성. 동체 각속도·투영중력·속도명령 + 이전행동 5프레임 |
| 행동 | 12차원 관절 각도 변위, scale 0.25 rad |
| 제어 주파수 | 50 Hz (PCA9685 + 서보 응답의 현실적 상한) |
| 도메인 랜덤화 | 동체 질량, 무게중심 전후 ±15mm, 지면 마찰, **제어 지연 0~40ms**, **서보 영점 오차 ±8°**, 위치 게인, 외란 |

```
관측을 두 가지로 두고 비교하는 것이 본 프로젝트의 설계상 핵심 판단이다.

취미용 위치제어 서보(DS3235)는 관절 위치를 되읽을 수 없고 PCA9685는 쓰기 전용이다.
즉 4족보행 강화학습의 표준 관측인 관절각·관절각속도를 실물에서 얻을 수 없다.
통상 이 자리에 이전 행동값(명령한 관절 목표)을 대신 넣지만, 본 팀의 실측은 그
대체가 위험함을 보여준다 — 40mm를 명령했을 때 실제로 들린 높이가 20mm를 명령했을
때보다 낮았다. 서보가 명령을 따라가지 못하는 구간에서 명령값과 실제 관절각이 크게
벌어지기 때문이다.

따라서 관절 피드백이 있는 A안과 없는 B안을 같은 조건에서 학습시켜 성능 차를 측정한다.
그 차이가 곧 피드백 센서 추가(포텐쇼미터 탭 또는 시리얼 버스 서보 교체)의 정량적
근거가 된다. 추측이 아니라 측정으로 하드웨어 사양을 결정하는 접근이다.

동체 선속도는 두 안 모두 관측에서 제외했다. 상태 추정기나 깊이 카메라 없이는 실물에서
얻을 수 없으므로, 학습 단계에서 그것에 의존하면 이식 자체가 불가능해진다.
```

### 프로젝트 주요기능

**① 실측 기반 기구 모델 정정 — 본 프로젝트의 핵심 성과**

```
조립된 로봇을 직접 계측해 공개 코드의 기구 파라미터를 바로잡았다.
```

| 파라미터 | 기존 공개값 | 실측값 | 오차 |
|---|---|---|---|
| 대퇴 `l3` | 100 | **125** | +25% |
| 하퇴 `l4` | 100 | **138** | +38% |
| 다리 전체 | 200 | **263** | **+31%** |
| 앞뒤 어깨축 `L` | 140 | **185** | +32% |
| 좌우 어깨축 `W` | 75 | **78** | |
| 어깨-대퇴 `l1` / `l2` | 50 / 20 | **56 / 20** | |

```
치수를 바로잡고 지지 다각형을 무게중심에 맞추자 별도의 좌우 보정 없이 전진했다.
같은 SpotMicro를 만드는 누구에게나 그대로 적용되는 결과다.
```

**② 규칙 기반 보행 — 실물 검증 완료**

| 항목 | 값 |
|---|---|
| 보행 상태 | 지면에서 안정적 전진, 좌우 트림 보정 0 |
| 보폭 / 몸통 높이 | −70 mm / 110 mm (조절 범위 60~130) |
| 네 발 지지 비율 | 71.4% (주기 1400 ms, 스윙 비율 0.143) |
| 착지 프로파일 | `(1−cos 2πt)/2` — 착지 수직 속도 0 |
| 무릎 최대 각속도 | 318°/s (DS3235 무부하 정격 545°/s의 58%) |
| 전진 속도 | `[ m/s ]` |
| 연속 보행 거리/시간 | `[ m / 초 ]` |

```
보행의 트레이드오프를 정량화해 조작 가능한 축으로 분리했다. 주기가 전진 속도를,
스윙 비율이 네 발 지지 비율을 각각 단독으로 정하므로 한 번에 한 축씩 조정할 수 있다.
발을 더 높이 들려면 두 값을 함께 올려야 한다 — 주기를 그대로 두고 스윙 비율만
올리면 대각선 두 발로 버티는 구간이 길어져 주저앉는다. 반대로 함께 올리면 무릎
요구 각속도가 오히려 떨어져(318 → 214°/s) 서보가 명령을 실제로 따라간다.
```

**③ 폰 기반 실시간 보행 튜닝**

```
로봇을 보면서 웹 브라우저로 보폭·몸통높이·발 들어올림·보행 주기·스윙 비율·다리별
트림·기울기를 즉시 조정하고, 전후좌우·회전 6방향으로 주행한다. 값은 파일로 저장되어
재시작 후에도 유지된다.

조작 중에 네 발 지지 비율·무릎 요구 각속도·전진 속도가 실시간으로 함께 표시되며,
서보 정격을 넘거나 지지 비율이 위험 구간에 들어가면 색으로 경고한다. 파라미터를
바꾸는 행위와 그 물리적 결과를 같은 화면에서 보게 한 것이 핵심이다. 키보드 앞에서
추측으로 값을 바꾸던 방식에서 벗어나 촬영하면서 조정할 수 있다.
```

**④ MuJoCo 강화학습 파이프라인 (`kinetiq/`)**

```
시뮬레이션 모델 자체에서 세 가지 문제를 찾아 수정했다. 이것을 고치지 않았다면
학습한 정책은 실물에 이식될 수 없었다.

  · 액추에이터가 토크 제어 → 위치 제어로 전환 (실물은 위치제어 서보)
  · 총 질량을 실측값으로 교정 (공개 모델은 관성 텐서가 전부 플레이스홀더였다)
  · 트랙폭 176 → 190 mm, 어깨-대퇴 수직 오프셋 20mm 복원

시뮬레이션 모델을 공개 URDF에서 변환하지 않고, 실측 기구 상수에서 직접 생성하도록
만든 것이 이 문제들의 재발을 구조적으로 막는다. 역기구학과 시뮬레이터가 같은 상수를
import 하므로 한쪽만 고쳐 어긋나는 일이 불가능하다. 관절 가동 범위도 URDF가 아니라
실측 서보 영점에서 유도한다 — 공개 URDF의 범위를 그대로 쓰면 기립 자세의 무릎 각도가
잘려 로봇이 주저앉는다.
```

**모델 검증** — 학습 전에 통과시키는 게이트

| 게이트 | 결과 |
|---|---|
| 순기구학 대조 (시뮬 발끝 vs 역기구학 발끝) | 4다리 × 40자세에서 **최대 오차 0.0000 mm** |
| 총 질량 | 2.20 kg (실측 일치) |
| 관성 텐서 | 등가 회전반경 2~300 mm (플레이스홀더면 4자릿수로 이탈) |
| 기립 안정 | 5 cm 낙하 후 정착, 처짐 1 mm |
| 무게중심 전후 위치 | −25.2 mm (앞발 하중 실측에서 유도한 값과 일치) |

```
순기구학 대조가 가장 중요하다. 시뮬레이터와 실물 제어 코드가 같은 기하와 같은 부호
규약을 쓴다는 것을 증명하므로, 학습한 정책의 관절 명령을 별도 변환 없이 실물 서보
드라이버에 넘길 수 있다. sim-to-real 전이에서 가장 흔한 실패 원인을 학습 전에 제거한다.

이 검증 과정에서 새 사실도 나왔다. 정지 상태 무게중심은 설계대로 −25 mm이지만,
기립 자세에서는 다리가 뒤로 기울며 −36 mm까지 이동한다. 다리 질량 1.02 kg이 함께
뒤로 가기 때문이며, 대각선 지지선과 11 mm 어긋난다. 계측만으로는 보이지 않는 값이다.
```

| 항목 | 값 |
|---|---|
| 기립 자세 | 동체 높이 119.8 mm (실물 운용값 110~130 mm와 일치) |
| 서보 처짐 / 최대 토크 | 1.08° / 0.566 N·m (DS3235 정격 35 kg·cm ≈ 3.4 N·m) |
| 학습 처리량 | 5,604 steps/s (12환경 병렬, CPU) — 2천만 스텝 약 60분 |
| **정책 추론 시간** | **0.153 ms/스텝 — 제어 주기 20ms의 0.8%** |
| 학습 결과 | `[ 평균 전진 속도 / 생존 시간 / 보상 곡선 ]` |

**구동 및 시연**

```bash
git clone --depth 1 https://github.com/robertchoi/oss_spotmicro.git
cd oss_spotmicro && uv sync          # GPU 불필요

uv run python -m kinetiq.eval --run runs/walk --render   # 학습 없이 정책 재생

```

### 기대효과 및 활용분야

```
첫째, 재현 가능성이다. 상용 4족보행 로봇도 독점 시뮬레이터도 없이, 100만원대
부품과 CPU만으로 4족보행 로봇의 제작부터 보행 제어, 강화학습까지 전 과정을
재현할 수 있다. 로보틱스 교육과 입문 연구의 진입장벽을 실질적으로 낮춘다.

둘째, 기구 파라미터 정정 결과는 SpotMicro 계열 프로젝트 전체에 즉시 적용된다.
같은 문제로 막혀 있던 사용자들이 원인 규명 단계를 건너뛸 수 있다.

셋째, 11주간의 개발 일지를 실패 기록과 함께 공개한다. 전원 설계 실패의 원인 분석,
제어보드 고장에 따른 전환 과정, 배선 변경 이력까지 그대로 남겨, 결과물만으로는
전달되지 않는 시행착오의 맥락을 제공한다.

향후 지형 인식과 카메라 기반 인지로 확장해 다양한 지면에 적응하는 보행으로
발전시킬 수 있다.
```

### 기타

**혁신성 및 차별성**

```
· 실물과 모델의 불일치를 문제의 근원으로 규명하고 실측으로 해결했다. 파라미터
  조정이 아니라 원인 제거로 접근한 점이 기존 사례와 다르다.
· 전 스택을 OSI 인증 오픈소스로 구성해 GPU 없이 재현된다. 4족보행 강화학습
  연구가 대부분 고가 상용 로봇과 독점 시뮬레이터를 전제하는 것과 대비된다.
· 토크 피드백이 없고 지연이 큰 취미용 위치제어 서보를 전제로 정책 설계와 도메인
  랜덤화를 구성했다. 제어 지연과 서보 영점 오차를 학습에 포함한 것이 그 예다.
· 규칙 기반 보행과 강화학습 보행이 동일한 기구 파라미터와 서보 인터페이스를
  공유해, 두 방식을 같은 하드웨어에서 직접 비교할 수 있다.
· 시뮬레이션 모델을 사람이 편집하는 파일이 아니라 실측 상수에서 생성하고, 실물
  제어 코드와의 일치를 순기구학 대조로 증명한 뒤에야 학습을 시작한다. 모델 불일치가
  이 프로젝트를 몇 주 막았던 문제였으므로, 그 재발을 검증 절차로 봉쇄했다.
```

**한계점 및 향후 로드맵**

```
강화학습 보행은 시뮬레이션 모델 검증과 학습 파이프라인 구축까지 완료했으며,
실물 이식은 진행 중이다.

가장 큰 제약은 하드웨어에 관절 피드백이 없다는 점이다. 취미용 위치제어 서보는
관절 각도를 되읽을 수 없어, 강화학습 보행의 표준 관측 중 절반(관절각·관절각속도)을
실물에서 얻을 수 없다. 본 팀은 이를 우회하지 않고 정면으로 다룬다 — 관절 피드백이
있는 경우와 없는 경우를 시뮬레이션에서 동일 조건으로 학습해 성능 차를 측정하고,
그 결과로 센서 추가 여부를 결정한다. 선택지는 서보 내부 포텐쇼미터 탭(약 2만원)과
피드백 내장 시리얼 버스 서보 교체(약 25만원)이며, 성능 차가 근거가 된다.

그 밖의 남은 과제는 다음과 같다.

  · 학습된 정책의 실물 이식 및 규칙 기반 보행과의 정량 비교
  · 링크별 질량 배분 실측 (총 질량 2.2kg은 확정, 부품 단위 배분은 추정치)
  · IMU(BNO085) 배선 및 서보 구동 중 I2C 안정성 검증
  · 서보 전원 계통 비상 정지 스위치 — 강화학습 정책은 규칙 기반보다 예측 불가능한
    명령을 낼 수 있어 실물 이식 전 필수
  · 경사·요철 지형으로 학습 환경 확장

무게중심을 전방으로 옮겨 다리를 수직에 가깝게 만들면 추진력이 최대가 될 것으로
계산되며, 이는 하드웨어 배치 변경으로 대응할 예정이다.
```
