## 주요기능 칸 끝에 — 구동 및 시연

양식이 주요기능 칸에서 "구동 테스트 완료 후 실행/시연 방법"을 요구합니다. 지금 가안에
이 부분이 빠져 있고, 로봇 없이 재현된다는 것이 본 프로젝트의 강점이라 반드시 넣어야
합니다.

```
로봇도 GPU 도 없이 이 보고서의 검증 가능한 주장을 전부 재현할 수 있다.

  git clone --depth 1 https://github.com/robertchoi/oss_spotmicro
  cd oss_spotmicro && uv sync
  make verify   # 모델과 실측 기구가 일치하는지 8게이트로 확인
  make eval     # 학습된 정책을 재생하고 서보 정격 초과 여부를 판정

로봇이 있으면 두 줄이 더 있다.

  cd RaspberryPi && python start_automatic_gait.py
  폰 브라우저로 http://<로봇IP>:8080 에 접속하면 걸으면서 조정할 수 있다
```

| 명령 | 확인하는 것 | 로봇 |
|---|---|---|
| `make verify` | 시뮬레이션 모델이 실측 기구와 일치하는가 (8게이트) | 필요 없음 |
| `make gait-check` | 같은 궤적을 재생했을 때 속도가 실물과 맞는가 | 필요 없음 |
| `make eval` / `make train` | 정책 실행 가능성 판정 / 재학습 (CPU) | 필요 없음 |
| `cd RaspberryPi && python start_automatic_gait.py` | 실물 보행 | 필요 |

```
부품이 다르면 자기 실측값을 한 곳에 넣고 make verify 를 돌리면 된다. 시뮬레이션
모델과 실물 제어 코드가 함께 따라오고, 8게이트가 맞는지 알려준다. 같은 검증을 매
푸시마다 CI 가 실행하며 커밋된 모델이 상수에서 생성한 것과 같은지도 함께 본다.
```

## 기대효과 및 활용분야

```
수천만 원대 상용 4족보행 로봇도, 독점 시뮬레이터도, GPU 도 없이 46만원어치 부품과
CPU 만으로 제작부터 보행 제어, 강화학습까지 전 과정을 재현할 수 있다. 로보틱스를
시작하는 학생과 입문자가 부딪히는 비용 장벽과 환경 장벽을 함께 낮춘다.

기구 치수를 바로잡은 결과는 SpotMicro 계열 저장소 전체에 그대로 적용된다. 같은
문제로 막혀 있던 사람이 원인을 찾는 단계를 건너뛸 수 있다.

11주 개발 일지를 실패 기록과 함께 공개한다. 전원 설계를 두 번 바꾼 과정, 제어보드가
고장나 교체한 일, 배선을 다시 한 이력이 그대로 남아 있다. 성공한 결과만 공개하면
다음 사람은 같은 실패를 처음부터 다시 겪는다.

앞으로는 지형 인식으로 확장한다. Intel RealSense D435 를 보유하고 있으며 상단 커버
설계가 먼저다. 카메라를 얹으면 무게중심이 바뀌므로 모델을 다시 검증해야 한다.
```

## 기타 — 프로젝트의 혁신성 및 차별성

> **가안 317행의 Isaac Lab 문장을 이것으로 바꾸십시오.** 우리는 MuJoCo 로 전환했고,
> Isaac Lab 은 독점 소프트웨어라 "전 스택이 오픈소스"라는 서술과 어긋납니다.

```
· 부품이 달라도 이어받을 수 있는 구조를 만들었다. 하드웨어 오픈소스는 부품이 바뀌면
  포크가 갈라진 채 돌아오지 않는다. 그래서 "받으면 바로 걷는다"고 약속하지 않는다.
  대신 로봇이 없는 사람은 클론 즉시 검증과 정책 재생을 실행할 수 있고, 로봇을 만드는
  사람은 자기 실측값을 한 곳에 넣으면 시뮬레이션 모델과 제어 코드가 함께 따라온다.
  부품이 다른 것이 이 문제의 본질이므로, 그것을 흡수하는 구조 자체가 기여다.

· 기하뿐 아니라 동역학까지 맞췄다. 모델을 사람이 편집하는 파일로 두지 않고 실측
  상수에서 생성하며, 상수마다 무엇으로 어떻게 쟀는지를 코드에 적어 두었다. 값만
  전달되고 근거는 전달되지 않던 것이 본 프로젝트가 발견한 문제였다.

· 독점 시뮬레이터를 쓰지 않기로 했다. 당초 NVIDIA Isaac Lab 으로 기획했으나 독점
  라이선스가 "누구나 재현할 수 있어야 한다"는 목표와 맞지 않아 MuJoCo 로 전환했다.
  그 결과가 "GPU 불필요"로 남았고, 심사 과정에서 누구나 같은 명령으로 확인할 수 있다.

· 학습된 정책이 서보 정격을 넘는지 배포 전에 자동으로 판정한다. 이번 정책이 실제로
  그 판정에 걸려 실물 이식을 보류했다.
```

## 기타 — 한계점 및 향후 발전 로드맵

```
강화학습은 파이프라인과 모델 검증을 마쳤으나 실물 이식은 아직이다. 정책은 규칙
기반보다 2.8배 빠르지만 무릎 각속도가 서보 정격의 194% 라 그대로 올리면 서보가
상한다. 다음 과제는 각속도를 보상 제약으로 넣어 정격 안으로 들이는 것이며, 속도에
2.8배의 여유가 있으므로 맞바꿀 수 있다고 본다.

도메인 랜덤화를 켠 학습은 다섯 설정 모두 정지 자세로 수렴했다. 원인을 항목별로
갈라 두었다. 지면 마찰이 전진 속도를 78%, 서보 영점 오차 ±8도가 71% 깎는다.
해결은 남은 과제다.

  · 로봇이 자기가 넘어진 것을 모른다. 스윙 비율 0.21 에서 뒤로 넘어졌는데 IMU 가
    없어 쓰러진 채로 보행 명령을 계속 냈고 로그에도 흔적이 남지 않았다. 검증 게이트가
    가리키던 무게중심 이탈과 같은 실패다.

  · 직진 편향의 원인은 조립 오차가 아니라 고장난 관절이었다. 한 세션에서 트림 조합
    162개를 시도했는데 그 전부에서 왼쪽 뒷다리는 −5에 붙어 있고 오른쪽 뒷다리만
    +5에서 +8로 올라갔다. 두 다리 격차가 13mm까지 벌어졌는데도 편향이 남았다. 값을
    못 찾은 것이 아니라 움직이는 관절을 쫓고 있었다. 해당 무릎은 8/19 이후 스플라인
    한 톱니에 해당하는 12도를 이미 오프셋으로 흡수한 상태였다. 오프셋은 고정된
    오차를 보정하는 값이라 이 경우에는 답이 되지 못한다. 부품 교체가 필요하다.

  · ROS 생태계와는 아직 연결되지 않는다. RViz, MoveIt, ros2_control 이 모두 URDF 를
    요구하는데 현재는 MuJoCo 모델만 생성한다. 표준을 몰라서가 아니라 순서를 뒤로
    미룬 것이며, 같은 상수에서 URDF 도 생성해 두 모델의 순기구학이 일치하는지를
    검증 게이트로 잡는 것이 다음 단계다.

  · IMU(BNO085) 장착, 서보 전원 비상 정지 배선, 링크별 질량 배분 실측이 남아 있다.
    비상 정지는 코드가 이미 있고 저항 하나와 배선 한 가닥만 연결하면 된다.
```

다시 열어 6V 기준으로 통일하고 나서야 우리가 만든 로봇을 정확히 설명할 수 있었다.

|---|---|
| **데이터 정제 / 가공 방법 요약** | 개인정보가 포함되지 않습니다. 관측값은 동체 각속도, 투영 중력, 속도 명령, 행동 이력이며 전량 시뮬레이터가 생성한 값입니다. 별도의 비식별화 조치가 필요하지 않습니다. 도메인 랜덤화 폭은 실측에 근거했습니다. 서보 영점 오차, 무게중심 전후 위치, 지면 마찰, 제어 지연을 실기에서 관측한 범위로 흔듭니다 |
